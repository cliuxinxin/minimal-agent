# Runner task brief

Read the workbench design. Own miniagent/agent.py, miniagent/model.py, new miniagent/context.py, miniagent/tools.py (only execution context), and focused tests. Do not edit web/config/frontend/programming/search files.

## Deliverables and interfaces

- ModelReply gains optional usage: dict | None = None, normalized keys input_tokens/output_tokens/total_tokens (only known nonnegative integers). Preserve OpenAI streamed usage and Anthropic message_start/message_delta usage including cache input when reporting totals; reject/ignore malformed optional usage without invalidating valid content. Keep compatibility with three-positional-field ModelReply. Do not add unsupported stream parameters to generic endpoints; request usage only where the interface supports it without changing existing compatible behavior.
- Agent emits usage events {input_tokens,output_tokens,total_tokens,model_calls,tool_calls,known_usage_calls}, and checkpoint events with no native history in the event data. Emit checkpoint after user append, validated assistant append and each committed tool result. Host reads agent.history at that moment. Keep tool call/result order and native Anthropic blocks correct. A result must be appended before its checkpoint; emit tool_result for presentation and then checkpoint. Do not duplicate tool outcomes.
- RunResult optional metrics dict with model_calls/tool_calls/input_tokens/output_tokens/total_tokens/known_usage_calls/elapsed_seconds/compactions. Unknown token counts are None. Existing positional calls stay valid.
- Agent has context_summary (string default empty) and compaction_count; host persists/restores them separately. At a conservative 60000-character request-history threshold, summarize only completed old rounds while retaining at least the latest two user-task groups and complete tool pairs. Large single-task histories must also be reducible at complete round boundaries. Produce bounded 6000-character summary using same provider with no tools, count its request in max_steps, emit context_compaction start/completed/error events and checkpoint after successful replacement. Include summary in subsequent system prompt. Preserve a full archive attribute/history history_archive (or explicit checkpoint archive payload kept local) so host can persist the complete original history; agree exact interface with root. Fail clearly on compaction failure; no repeated attempt loop or tool replay. Preserve signed/native retained blocks verbatim. Respect cancellation and remaining model-call budget.
- Extend tool_execution_context with optional per-run context ID accessible as execution_run_id(); wrap every tool call with the Agent run_id so search fetch cache is scoped to one run. Existing calls remain valid.
- Keep current stall detection, streaming validation and stop behavior. Tests must cover both providers' usage, exact checkpoint history, compaction paired calls/native blocks/cancellation/budget.

Report code changes, tests and concrete limitations to root; do not commit or publish. Do not spawn subagents. Backend sockets in tests may require approved require_escalated execution.
